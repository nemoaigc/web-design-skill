# 自验与线上复验

## 本地清单

1. `node scripts/audit_site.mjs http://localhost:<端口>/ <内页...>`：横向溢出、原生控件、坏图、顶部固定层、页面报错全部为 0 或合规。
2. `bash scripts/grep_native_controls.sh <项目目录>` 为 0。
3. 每个按钮、链接、表单都点一遍，看到真实结果：成功、错误、空状态各一次。
4. `prefers-reduced-motion: reduce` 下动效降级、内容完整。
5. 390 和 1440 各截首屏，自己先看：图都加载了、文字没被裁、没有空壳区块。
6. 手机端扫 320–430 几个宽度和横屏：按钮缩小换行而不是被裁，长文案不溢出。
7. 多语言页面每种语言各开一个全新的浏览器上下文看一遍，最长的语言最容易溢出。

## 截图

交给用户或要放进别的页面的截图不许有半张元素，半张卡片、被切掉的文字看起来就是 bug：

- 裁切线落在两个完整元素之间，截完逐张查底边。
- 用加高的视口截，等入场动画播完；整页截图会让滚动动画重播，截到半透明的中间态。
- 界面本身的截断（省略号、表格横滚）先修界面，不靠裁图遮掉。

## 线上复验

1. 部署命令返回成功不等于已上线。先取线上页面，找到这次改动的特征文字或版本标记，对上了再往下验。
2. 对线上地址再跑一次 `audit_site.mjs`。
3. 走一遍核心流程并真实提交，测试记录用 `E2E` 开头标记。
4. 在后台或数据库里看到这条记录。
5. 删掉测试记录及关联数据；删除脚本放项目外，不打印数据库连接串。复查列表回到原样，汇报写明删了几条。删不掉就先别提交。
6. 第三方脚本（统计、客服插件）被安全策略拦截的问题常常只在线上出现，在线上收一遍控制台报错。

## "改了没生效"先查

| 现象 | 常见原因 |
| --- | --- |
| 部署成功，线上还是旧内容 | 发到了预览环境，或部署失败后还挂着上一个版本 |
| 线上读到的是本地配置 | 构建时把本地 `.env` 烤进了静态页面 |
| 改了环境变量没用 | 变量只在新的部署里生效，或改错了环境 |
| 本地改样式不生效 | 开发服务器的构建缓存是旧的，清缓存重启 |
| 元素多出描边、阴影或透明度 | 自定义 class 和工具类框架的同名类撞了，自定义 class 加前缀 |
| 部署包很大、带了截图 | 发布工具把工作目录整个上传了，中间产物放项目外 |

## 组件库的验证陷阱

- 弹层关闭时退场动画期间元素还在 DOM 里，断言"不存在"会误判；断言关闭状态或等动画结束。
- 不要在组件库的触发器上再叠自己的开关逻辑，会和内部状态打架，表现为点一下开、马上关。
- 下拉和弹层常渲染在 portal 里，查元素要从 document 查，不从组件容器查。
