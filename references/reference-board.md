## 按产品类型找

- **内容站、官网、落地页**：画廊起步，再补同行业真实站点。行业惯例（分类条、购物车位置、预约流程）去真实站核对。
- **应用、后台**：同类 SaaS 登录后的真实界面和 Mobbin、Nicelydone 的截图，营销首页不算。
- **工具型产品（画布、编辑器、生成器、节点工作流）**：营销页和真实界面差得最远，几乎不能当参考。按这个顺序找：
  1. 同类产品登录后的界面：AI 画布和设计 Agent（Lovart、Flora、Krea、Visual Electric、Freepik Spaces、Firefly Boards）、画布和白板（tldraw、Figma、Miro、Canva、Kittl）、节点工作流（Figma Weave、Krea Nodes、ComfyUI 类）。
  2. Mobbin、Nicelydone 里搜 canvas、editor、AI image 等。
  3. 产品所在行业的同类工具（国内外都看）。
  4. 最后用画廊补首页和版式。

  按界面区块对应截图：外壳和导航、首页或项目列表、画布、工具栏、属性面板、对话或提示词栏、结果页、模板库。

要登录的站请用户自己登录，再截具体界面。账号里的偏好问卷、设置由用户自己选。

## 来源要换着用

每次都从同两三个画廊挑，用户会说"每次都见过"。每轮至少：

- 从总目录里换开两三个没用过的画廊；
- 找一两个同行业的真实产品或真实站点。

用户说"范围太小"，就是只看了少数几家，按上面三类各补一批。

## 两种"抄"

- **抄行业惯例**是调研，应该做：用户的肌肉记忆（导航放哪、筛选怎么排、购物车在哪）在这里原创是负分。
- **抄具体作品**走不通：逐像素克隆会和自己的功能打架，也有版权问题。
- 不凭记忆造界面，去抓真站截图核对。

## 借什么

- 借结构、比例、交互骨架。用户选定参考后，首屏结构要贴近原版。
- 颜色、文案、图片、品牌自己定，1:1 照搬不行。
- 用户贴截图时，默认只借"有哪些控件、选项是什么"，样式沿用我们自己的；拿不准先问。
- 用户给方向词（"大胆""黑白""像某站"）时，先列出要做哪几个组件、各借参考哪一块、配色字体怎么定，点头后再写代码。

## 交给用户的格式

1. 先逐张自审：营销页、骨架屏、被弹窗挡住的、和别的方向撞了的、一眼普通的（左文右图、白卡片网格、常规后台换主色）都剔掉。
2. 每个方向一句话：借哪个参考的哪一块 + 配色 + 字体 + 图片处理。
3. 2–4 个差异明显的方向，标推荐和理由，用户回字母即可。
4. 截图存在项目目录之外（例如 `<项目>-refs/`），别放进源码目录：部署可能把工作目录整个上传。

## 截图工具

- 桌面宽度用 Playwright 截（浏览器面板模拟 1440 不够大）。
- `waitUntil` 用 `domcontentloaded` 或 `load` 再多等几秒，不用 `networkidle`（开发服务器的热更新永远不空闲，有的站一直有请求）。
- 截完逐张看：有没有半张元素、弹窗、骨架屏、Cookie 横幅。
