# 视觉规矩

都是用户否掉过、又容易再犯的。用户当次说法和这里冲突时，以用户为准。

## 颜色

- 主色只用在按钮、当前项、价格、强调标记上，不铺整块色面。大块主色面板会被判"太重、单调"。
- 颜色按场景和行业定，不预设统一主色；同一批项目之间要拉开，避免撞色。给 2–3 个配色方向让用户选。
- 避开 AI 默认配色：暖米色配赤陶、紫色、蓝到紫渐变、金色或橙色当重点色。
- 背景不用点阵和网格，不加随机光斑、多层噪点。
- 照片和配图不默认暖光：白要是白，产品颜色要准。
- 参考站的配色不照搬。

## 字体

- 字体从行业里长出来，先说清为什么这个行业用这套字，再给 2–3 个方向。
- Inter、Space Grotesk 这类最常见的字体，选之前先找替代。
- 字体文件放进项目本地加载，只取用到的子集，配真实的系统回退栈；中文回退系统无衬线。构建不依赖外网，国内访问也不会卡在 Google Fonts。

## 首屏和顶部

- 首页是第一印象，设计预算优先给首屏和前两屏。
- 首屏默认居中上下排，不做左文右图。参考站本身是左右的才跟。
- 选定参考后首屏结构贴近原版，颜色仍自己定。
- 任何宽度下顶部只有一条导航，不叠提示条、公告条。窄屏时次要项收进菜单，不折行；在 390、768、1024、1440 四个宽度数层数。
- 工具型产品首屏要秒开、直奔工作区：不放开场动画，不接管滚动。

## 导航

- 顶栏只放：品牌、少量入口、一个主行动按钮、菜单按钮。其余收进菜单。
- 后台或管理入口不放顶栏，放菜单底部和页脚。
- 应用和后台用侧栏或顶栏放模块，同样只有一层、入口少。
- 菜单：开约 240ms、关约 160ms；点链接后关闭；Esc 关闭。

## 控件和状态

- 不用浏览器原生控件：下拉、日期、时间、复选、单选、滑块、颜色选择、校验气泡都换成自定义组件（项目已有组件库就用它的）。原生控件弹出来太粗糙，和页面风格对不上。
- 表单关掉浏览器自带校验，错误文案自己显示在字段旁；数字输入隐藏上下箭头。
- 状态要齐：提交中按钮禁用并显示进度；失败时保留已填内容、可以重试；空状态告诉用户下一步做什么；加载失败不用空列表冒充"没有数据"；未登录、无权限、会话过期分开提示。
- 截图少的页面，用流程图、结构图、图标或配图把内容讲清楚。生成的配图先给用户看一眼再放。

## 卡片、圆角、阴影

- 卡片用 1px 细描边，不用硬投影；只有悬浮条和弹层用柔和阴影。
- 按钮不用黑色粗边框。
- 同类区块先复用项目里已改好的组件，不另写一个简版。

## 同站各页

- 各页按功能换版式，不要每页都是同一套卡片网格换内容。共享的是配色、字体和组件。
- 手绘、做旧这类装饰只放在插画、图案、加载动效上；表格、表单、设置这类要读数和操作的页面保持朴素。

## 动效

- 每个项目一套自己的节奏，按行业和内容定：精确的工具用短促（约 0.2s）、有分量的商品用顺滑、画册感的内容用慢柔（0.6–0.9s）。先给方向让用户定，再写。
- 动效从业务里来：数字滚动给报价，依次点亮给进度，逐项打勾给清单。
- `prefers-reduced-motion` 下取消位移和旋转，内容静态完整可见。

## 被否掉的做法

| 做法 | 为什么不行 |
| --- | --- |
| 旋转流光边框、光晕、鼠标跟随光斑、按钮彩色扫光 | 和业务无关的炫技，被判丑 |
| 大块实色主色面板 | 太重、颜色单调 |
| 蓝紫渐变按钮和标题 | AI 默认感 |
| 金色、橙色做重点色 | 用户明确不要 |
| 黑白极简整页 | 太冷，像没做完 |
| 照搬参考站的颜色或按钮样式 | 1:1 照搬，失去自己的风格 |
| 同类区块另写简版 | 和已有组件不统一，显得粗糙 |
| 统一风格时顺手改了没让改的区块 | 超出范围，要先问 |
